# mgesture 0.3.0

mgesture 0.3.0 makes physical hand selection and everyday scrolling more reliable while fixing a serious reset safety issue. It also adds an explicit, verified updater so standalone installations can move to the latest stable release without losing user state.

## ✨ Highlights

- Select a physical right or left hand, or let mgesture choose and lock one hand automatically.
- Calibrate/confirm camera handedness separately from the mirrored preview and pointer direction.
- Use a more natural, jitter-tolerant two-finger scroll pose with clear tutorial diagnostics.
- Run `mgesture update` to stage, verify, self-test, and activate the newest stable release.
- Reset user state safely without deleting the installed application.

## ✨ New Features

### Physical hand selection

The application now supports `right`, `left`, `either`, and `auto` hand-selection modes. The selected physical hand is normalized before gesture processing, and both hands use the same left-click, right-click, hold, drag, and scroll meanings. `mgesture --hand left|right|either|auto` is available as a per-run override.

### Camera handedness controls

The first-run tutorial confirms the physical hand against the camera's MediaPipe orientation. `--mirror auto|on|off` provides a per-run troubleshooting override. Preview mirroring and pointer mirroring remain separate from handedness interpretation.

### Built-in updates

Run:

```sh
mgesture update
```

to update the current native platform to the latest stable GitHub Release, or:

```sh
mgesture update --check
```

to check without downloading. The updater selects the canonical target, verifies the release manifest and SHA-256 checksum through the existing installer, stages the archive, runs its packaged self-tests, and activates it transactionally.

### Reset preview

Use:

```sh
mgesture --reset --dry-run
```

to see the mutable user-state reset plan without deleting anything. `mgesture --reset --yes` remains available for deliberate non-interactive resets.

## 🎓 First-run Experience

The existing safe first-run tutorial now includes physical hand selection and camera-handedness confirmation. Tutorial practice continues to use the production gesture engine and fake input, so it cannot move or click the real mouse.

## ✋ Hand & Camera Improvements

- MediaPipe's documented selfie-relative handedness label is normalized into physical left/right before selection.
- Two detected hands are handled by one stable active-hand lock; the controller does not switch hands mid-drag.
- Unmirrored and mirrored input conventions are tested for both physical hands without adding a second normal-runtime inference.

## 🖱 Gesture Improvements

- Scroll entry now uses palm-normalized reach and finger straightness rather than one brittle distance ratio.
- Ring and pinky may be naturally relaxed rather than anatomically tightly folded.
- A neutral thumb is not treated as an active pinch-down; click and drag precedence remains first.
- Scroll entry progress, active state, finger readiness, movement delta, fractional remainder, and rejection reason are available to the tutorial/debug path.
- Brief active-pose or landmark dropouts receive a time-based grace period; sustained invalid input exits safely and resets the scroll anchor.

## ⬆ Built-in Updates

`mgesture update` is explicit and never runs automatically. It does not replace the active installation until target, manifest, checksum, architecture, packaged runtime, and native Mojo self-tests pass. A failed update leaves the current release in place, and a successful update preserves configuration, calibration, hand preference, and onboarding state.

## 🐛 Bug Fixes

- Fixed physical left/right hands being misinterpreted when raw camera orientation differed from MediaPipe's mirrored-input assumption.
- Fixed natural two-finger scroll poses being rejected by strict index/middle or folded-finger geometry.
- Fixed brief landmark jitter resetting scroll mode before a real user could scroll.
- Fixed the tutorial Scroll step providing no actionable explanation when one finger or pinch condition was not ready.
- Fixed `mgesture --reset` deleting installed application files in layouts where the standalone release root shared the platform user-data directory.
- Fixed Unix update activation so an atomic pointer replacement does not place the new pointer inside the previous release directory.

## 🛡 Safety & Reliability

- Reset uses validated canonical mutable targets only and protects the executable, release directories, bundled runtime, native Mojo library, model, and release metadata.
- Reset removes symlink entries without following them and is idempotent.
- Reset now proves the standalone executable remains usable in the release smoke path.
- Updates pin installer activation to the manifest version checked by the updater.
- Hand switching, hand loss, invalid landmarks, pause, camera failure, exceptions, and normal exit continue to release held buttons safely.

## ⚡ Performance

- Normal runtime still performs one MediaPipe inference per frame; handedness normalization is a cheap label transform.
- Scroll geometry adds only small 21-landmark arithmetic and does not add a second model or inference pass.
- No universal latency or CPU speedup is claimed without a hardware measurement.

## 🖥 Platform Improvements

### Linux

Linux standalone reset coverage exercises the shared user-data/install-root layout and preserves the extracted executable and native Mojo library.

### macOS

The canonical hand and mirror policy are platform-neutral; macOS standalone packaging and logical display behavior remain covered by the existing target matrix.

### Windows

The updater continues to use versioned release activation rather than overwriting the running executable, preserving the native Windows x86_64 and ARM64 packaging model.

## 🔧 Build & Release

Platform-independent quality checks now run once, while six Python and six Mojo target lanes retain native architecture, Mojo, parity, replay, and fake-input coverage. Main CI builds and smoke-tests exact-SHA candidate packages once; the release workflow reuses those verified bytes and still performs manifest, checksum, SBOM, provenance, and malware validation.

## 📦 Standalone & Distribution

The official workflow continues to publish six native standalone targets: Linux x86_64/ARM64, macOS Intel/Apple Silicon, and Windows x86_64/ARM64. Each package includes the native Mojo engine, Python fallback, pinned model, checksums, release manifests, SBOM, provenance attestation, and native package smoke validation.

## 🔧 Changed

- New configurations use automatic hand selection until onboarding records the user's choice; older configurations without the new field retain right-hand behavior.
- `camera.preview_mirror`, `vision.handedness_mirror`, and `gesture.pointer_mirror` make the three orientation concerns explicit while legacy fields remain readable.
- The native Mojo ABI is version 2 because scroll exit grace is part of the fixed configuration record.

## ⚠ Breaking Changes

None.

## ⬆ Upgrade

Linux/macOS:

```sh
curl -fsSL https://github.com/christiandoxa/mgesture/releases/latest/download/install.sh | sh
```

Windows:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://github.com/christiandoxa/mgesture/releases/latest/download/install.ps1 | iex"
```

Existing standalone installations can use:

```sh
mgesture update
```

## 🚀 Getting Started

After installing or updating:

```sh
mgesture
```

Optional commands:

```sh
mgesture tutorial
mgesture calibrate
mgesture --reset --dry-run
```
