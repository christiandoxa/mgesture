# mgesture 0.2.0

mgesture 0.2.0 makes everyday startup and gesture control easier to use while hardening the real-time camera, gesture, input, and failure paths. Run `mgesture` after installation; safe onboarding teaches the controls before real mouse input is enabled.

## Highlights

- Start the application with the simple zero-argument `mgesture` command.
- Learn pointer movement, click, hold, drag, right click, scroll, pause, and safe exit in the first-run tutorial.
- Use `mgesture tutorial` to practice again or `mgesture --reset` to return to a fresh user state.
- Get more stable gesture behavior through deterministic arbitration, invalid-input suppression, and bounded newest-frame processing.
- Use improved multi-sample calibration, camera diagnostics, reconnect handling, and multi-monitor input support.

## ✨ New Features

### Interactive first-run tutorial

The first `mgesture` launch runs a concise interactive tutorial covering right-hand detection, pointer movement, left click, hold and drag, right click, scrolling, pause/resume, and emergency stop. Tutorial practice uses the production gesture engine with simulated input and cannot move or click the real mouse. Press `K` to skip; an interrupted tutorial runs again on the next launch.

### Replayable tutorial

Run `mgesture tutorial` at any time to practice the controls again without deleting calibration or settings.

### Simple user-state reset

Run `mgesture --reset` to clear mgesture configuration, calibration, onboarding state, recordings, logs, and application-owned cache while keeping the installed application and bundled assets. Use `mgesture --reset --yes` only for deliberate non-interactive use.

### Developer landmark recording

The opt-in `mgesture record-landmarks --developer --output PATH` command records timestamped landmark JSONL locally for fixture development. It does not record camera images, upload data, or emit mouse input.

## 🐛 Bug Fixes

- Reduced false actionable transitions by rejecting nonfinite, out-of-range, and degenerate landmark frames.
- Made ambiguous new pinch frames deterministic and prevented a held button from switching sides.
- Hardened release hysteresis, scroll dead-zone handling, and pointer-filter reset around gesture transitions and reacquisition.
- Dropped stale asynchronous hand-landmarker results and bounded pending inference work.
- Reconnected cameras after read failures with capped backoff and released held buttons on camera outages.
- Ensured dispatch, backend, signal, exception, and shutdown failures route through shared cleanup.

## ⚡ Performance

- Camera capture remains a one-slot newest-frame handoff; old frames and stale inference results are discarded instead of accumulating latency.
- Paused/no-hand scheduling and persistent MediaPipe contexts reduce unnecessary continuous work.
- Gesture work remains on CPU/Mojo; no GPU speedup is claimed without an end-to-end measurement.

## 🛡 Safety & Reliability

- Onboarding, calibration, replay, and automated tests use fake or observation-only input.
- Calibration requires multiple valid samples before saving thresholds.
- Hand loss, camera failure, invalid input, pause, exceptions, signals, and normal exit release held buttons.
- Reset requires confirmation by default and validates application-owned paths before deletion; installed binaries, bundled native Mojo, and bundled models are retained.

## 🖥 Platform Improvements

### Linux

X11 monitor discovery now uses active `xrandr` layouts and fails with actionable errors when display access is unavailable. Wayland `/dev/uinput` diagnostics report relative-only behavior and permission state.

### macOS

Quartz layout discovery covers active displays in logical coordinate points, including monitors positioned at negative coordinates. Accessibility guidance remains explicit.

### Windows

Native x86_64 and ARM64 input uses per-monitor DPI awareness and virtual-desktop coordinates, including negative monitor positions. WSL remains unsupported.

## 📦 Standalone & Distribution

The release workflow continues to build and verify six native standalone targets: Linux x86_64/ARM64, macOS x86_64/ARM64, and Windows x86_64/ARM64. Each bundle contains the target-native Mojo engine, Python fallback, pinned model, checksums, release manifests, SBOM, provenance attestation, and package smoke validation when the workflow completes successfully.

## 🔧 Changed

- `mgesture` is now the primary human-facing startup command; `mgesture run` remains available for scripts and advanced options.
- Calibration is optional and remains safe by default.
- Camera probing reports requested and negotiated resolution/FPS and automatic startup prefers the configured index before trying other readable cameras.
- README usage now leads with install, `mgesture`, gestures, tutorial, calibration, reset, and troubleshooting; platform terminology is Linux/macOS/Windows.

## ⚠ Breaking Changes

None.

## ⬆ Upgrade

Linux/macOS:

```sh
curl -fsSL https://github.com/christiandoxa/mgesture/releases/latest/download/install.sh | sh
```

Windows:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://github.com/christiandoxa/mgesture/releases/latest/download/install.ps1 | iex"
```

Existing installations may use `mgesture update`.
